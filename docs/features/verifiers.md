# Verifier Types

Smart contract verification methods for crypto bounties. Each verifier defines how an answer is checked on-chain.

Types 0–4 are verified by the Rust Anchor program on-chain.  
Types 5–8 are verified in TypeScript (server-side, faucet mints payout).  
Type 9 (`zk_rust`) is fully trustless — verified on-chain via SP1 ZK proof.

---

## On-chain (Rust, types 0–4)

### exact_number (Type 0)
**Use case:** Math problems with exact integer answers
```json
{ "type": "exact_number", "config": { "target": 42 } }
```
Submit: `"42"` — contract checks `submitted == target`

### exact_string (Type 1)
**Use case:** Pre-image puzzles, passwords, secret codes
```json
{ "type": "exact_string", "config": { "answerHash": "sha256hex..." } }
```
Submit: `"opensesame"` — contract hashes answer, compares to stored hash. Answer never stored on-chain.

### numeric_tolerance (Type 2)
**Use case:** Approximation problems, numerical methods
```json
{ "type": "numeric_tolerance", "config": { "target": 3.14159, "epsilon": 0.01 } }
```
Submit: `"3.14"` — contract checks `|submitted - target| <= epsilon`

### numeric_range (Type 3)
**Use case:** Bounded estimation, optimization bounds
```json
{ "type": "numeric_range", "config": { "min": 10, "max": 100 } }
```
Submit: `"42"` — contract checks `min <= submitted <= max`

### multi_numeric_tolerance (Type 4)
**Use case:** PDE solutions, multi-variable systems
```json
{
  "type": "multi_numeric_tolerance",
  "config": {
    "targets": [
      { "key": "x", "value": 3.0, "epsilon": 0.1 },
      { "key": "y", "value": 2.0, "epsilon": 0.1 }
    ]
  }
}
```
Submit: `"x=3.01,y=1.99"` — all variables must pass independently.

## TypeScript-verified (types 5–8)

These run server-side. Platform is the trusted oracle. Payout via faucet mintTo.

### hash_preimage (Type 5)
**Use case:** Commit-reveal, password puzzles
```json
{ "type": "hash_preimage", "config": { "targetHash": "sha256hex..." } }
```
Submit: `"the_secret"` — server verifies SHA256(answer) == targetHash

### sat (Type 6)
**Use case:** Boolean satisfiability problems
```json
{ "type": "sat", "config": { "numVars": 3, "clauses": [[1,2,-3],[-1,3],[2,-3]] } }
```
Submit: `"1,0,1"` — server verifies all clauses are satisfied

### wasm_exec (Type 8)
**Use case:** Custom logic, arbitrary deterministic verification (server-side trust)
```json
{ "type": "wasm_exec", "config": { "wasmBase64": "AGFzbQ...", "description": "..." } }
```
Submit: answer string — server runs WASM checker, must return 1. 3s timeout enforced.

## Trustless arbitrary (Type 9)

### zk_rust (Type 9) ★ New
**Use case:** Any deterministic problem where you want trustless verification. Turing complete.

Write a Rust checker, compile to SP1 zkVM, lock `vkeyHash` on-chain. Solvers generate a ZK proof locally. Anchor program verifies the proof with BN254 pairing — server cannot influence result.

```json
{
  "type": "zk_rust",
  "config": {
    "vkeyHash": "0x00bb9e57314d7ee4f65a4b9fb46fbeae0495f2015c5a8a737333680ce6bb424e",
    "description": "Checks if answer is pi to 6 decimal places"
  }
}
```

Submit: `{ "proof": "<base64>", "publicValues": "<base64>" }` — generated by `aof-zk prove`

**Trust model:** vkeyHash locked on-chain. Verification is pure math. Platform cannot fake results.  
**Proof generation:** 1-2 min CPU, ~1 min Succinct hosted prover.  
**CU cost:** 400K compute units per verification.

→ [Full zk_rust documentation](zk-rust.md)

## Fixed-Point Arithmetic (types 0–4)

The backend automatically converts human-readable floats to fixed-point integers (10^6 scale) before sending to the contract. Users submit normal numbers like `"3.14"`, not `"3140000"`.

---

## Choosing a verifier

| Problem type | Verifier |
|-------------|---------|
| Exact integer | `exact_number` |
| Secret / preimage | `exact_string` or `hash_preimage` |
| Approximation | `numeric_tolerance` |
| Multi-variable | `multi_numeric_tolerance` |
| Logic puzzle | `sat` |
| Custom logic, trust platform | `wasm_exec` |
| Custom logic, fully trustless | `zk_rust` |
| Anything else | `zk_rust` |

---

## Wrong answers are free

For types 0–4: wrong answers are caught during Solana simulation before broadcast — no gas spent.  
For types 5–8: wrong answers caught in TypeScript before any on-chain call.  
For type 9: wrong proofs caught in Solana simulation before broadcast.

Only correct answers trigger a real transaction.
